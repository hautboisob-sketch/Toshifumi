# どの端末からでも同じ環境で使うための構成

ローカルの Claude Code だけで運用していると、設定が自分のマシンの
`~/.claude/` に溜まる。**ここは同期されない。** 端末を変えた瞬間に、
慣れた指示もスキルも消える。

「どこでも同じ環境」にするというのは、`~/.claude/` に置いてあるものを
**リポジトリ**か**claude.aiアカウント**に移す作業のこと。それだけ。

## 1. 設定は3つの層に分かれている

| 層 | 置き場所 | どこまで付いてくるか |
| --- | --- | --- |
| ① リポジトリ | `CLAUDE.md` / `.claude/` | **全端末・全入り口。** git に入るので必ず付いてくる |
| ② claude.aiアカウント | アップロードしたスキル、コネクタ、クラウド環境 | **全端末。** アカウントに紐づく |
| ③ ローカルマシン | `~/.claude/` | そのマシンだけ。**他のどこにも行かない** |

ローカルセッションは ①②③ 全部を読む。
ブラウザ・スマホから開くクラウドセッションは **①と② だけ**を読む。

だから、どこでも効かせたいものは ① か ② に置く。

### ①に置けるもの（リポジトリに commit する）

- `CLAUDE.md` — 毎回読ませる前提知識
- `.claude/rules/*.md` — 特定ファイルを触るときだけ読ませるルール
- `.claude/skills/*/SKILL.md` — 呼んだときだけ読み込まれる手順
- `.claude/settings.json` — 権限、環境変数、フック
- `.mcp.json` — このリポジトリで使う MCP サーバー

### ②に置くもの（claude.ai の設定画面から）

- **個人スキル。** 複数のリポジトリで使う横断的なものはこっち。
  claude.ai の Settings から有効化しておくと、クラウドセッションが起動時に読み込む。
  例：`telop-analyzer`（テロップ分析）はリポジトリを問わず使うので②に置いてある。
- **コネクタ**（Gmail / Google Drive / Slack など）。アカウント単位なのでどこでも効く。

### ③に残していいもの

そのマシン固有のものだけ。エディタの好み、ローカルのパス。
**「どこでも使いたい」と思ったものが ③ にあったら、それは設計ミス。** ① か ② に移す。

## 2. 入り口は4つ。用途で使い分ける

| 入り口 | Claude が動く場所 | 向いている場面 |
| --- | --- | --- |
| ブラウザ `claude.ai/code` | クラウド | 外出先。手元に何も要らない |
| スマホアプリ（Code タブ） | クラウド | 移動中の確認・指示出し |
| ターミナル `claude` | 自分のマシン | 腰を据えた作業 |
| Remote Control | 自分のマシン | **自宅マシンのファイルを触りたいのにスマホしかない**とき |

分岐はひとつだけ：

- **リポジトリの中だけで完結する** → クラウドセッション（ブラウザ / スマホ）
- **ローカルのファイルが要る**（Premiere のプロジェクト、書き出した動画の実物）
  → Remote Control。クラウドVMからは自分のマシンのファイルは見えない

### ターミナルとクラウドの行き来

```bash
claude --cloud "運用フローの月次サイクルを見直して"   # ターミナルからクラウドに投げる
claude --teleport                                    # クラウドのセッションを手元に引き取る
```

`--cloud` はカレントディレクトリの GitHub リモートを clone する。
**手元のコミットは先に push しておく**（VM は GitHub から取るので、未push分は見えない）。

### Remote Control

```bash
claude remote-control        # マシンをサーバーにして待たせる。スペースキーでQRコード
claude --remote-control      # 普通に会話しつつ、外からも操作できる状態にする
/remote-control              # 作業中のセッションを途中から外に開く
```

QRをスマホで読めばそのまま続きから触れる。ノートを閉じたら切れるので、
出先から使う前提なら `tmux` の中で起動しておく。

## 3. 構築の手順

### Step 1 — GitHub を繋ぐ

`claude.ai/code` の初回セットアップで GitHub App を認可する。
すでにターミナルで `gh` を使っているなら `/web-setup` でトークンを同期するだけでもいい。

### Step 2 — リポジトリに `.claude/` を作る（このリポジトリは作成済み）

```
CLAUDE.md                              前提知識
.claude/settings.json                  権限
.claude/rules/ledger.md                台帳を触るときだけ効くルール
.claude/skills/post-check/SKILL.md     /post-check
```

**ここを commit した時点で、どの端末から開いても同じ振る舞いになる。**

### Step 3 — 個人スキルを claude.ai に上げる

`~/.claude/skills/` にあるスキルは、クラウドセッションからは見えない。
横断的に使うものは claude.ai の設定からアップロードして有効化する。

アップロードするスキルの frontmatter は6項目しか許されない
（`name` / `description` / `license` / `compatibility` / `metadata` / `allowed-tools`）。
それ以外のキーが入っているとアップロードがエラーで落ちる。

### Step 4 — クラウド環境を設定する

`claude.ai/code` のメッセージ入力欄の上にある雲アイコンから開く。設定できるのは3つ。

| 設定 | 使いどころ |
| --- | --- |
| ネットワークアクセス | 既定は Trusted。外部ドメインを叩くなら Custom で許可リストを足す |
| 環境変数 | `.env` 形式で1行1つ |
| セットアップスクリプト | セッション開始時に走る bash。依存を入れるならここ |

**環境変数に API キーやパスワードを入れない。** その環境を使う人全員から読める。

### Step 5 — スマホを繋ぐ

Claude アプリを入れて同じアカウントでログイン。ターミナルで `/mobile` を打つと
ダウンロード用のQRが出る。`/config` で通知を有効にすると、
長い作業が終わったときや判断を求めるときにプッシュが飛ぶ。

## 4. 「MDで操作する」の設計

3つある。分けて使う。混ぜると context が太るだけで効きが落ちる。

| 置き場所 | いつ読まれるか | 入れるもの |
| --- | --- | --- |
| `CLAUDE.md` | **毎回** | 前提、用語、絶対ルール、ファイルの役割 |
| `.claude/rules/*.md` | `paths:` に書いたファイルを触ったとき | そのファイル固有の書式ルール |
| `.claude/skills/*/SKILL.md` | 呼ばれたとき / 関連しそうなとき | 手順。長くていい |

判断の基準：

- **毎回知っていてほしい事実** → `CLAUDE.md`。ただし200行以内。
  長いほど読み飛ばされる。
- **特定のファイルを触るときだけの話** → `rules`。`paths:` で絞る。
  台帳のカラム規則を毎回読ませる必要はない。
- **手順・チェックリスト・繰り返す作業** → `skills`。
  呼ばれるまで読み込まれないので、長くても毎回のコストがゼロ。

`CLAUDE.md` が育って手順書になってきたら、それは skill に切り出す合図。

## 5. 引っかかりやすいところ

- **`~/.claude/CLAUDE.md` はクラウドに来ない。** 個人の口調や好みをそこに書いていると、
  ブラウザから開いた瞬間に別人になる。リポジトリの `CLAUDE.md` に移す。
- **未push のコミットはクラウドから見えない。** VM は GitHub から clone する。
- **クラウドVMはローカルのファイルを持っていない。** 動画の実物を見せたいなら
  Remote Control か、ファイルを添付する。
- **`承認済` の判断を自動化しない。** 台帳の承認ステータスは人が動かす。
- 決めたルールは会話に残さず、`CLAUDE.md` か `docs/` に書き戻す。
  書き戻していないルールは、次のセッションには存在しない。
