# 運用フロー（月次サイクル）

制作ではなく、代行業務としての回し方。

---

## 予約投稿ツールの実力

設計の前提になるので、先に上限を押さえる。

| | Meta Business Suite | TikTok Studio |
| --- | --- | --- |
| 予約できる範囲 | 20分後 〜 29日後（15分単位） | 15分後 〜 約30日後 |
| 予約キューの上限 | 1アカウント **25件** | **10件程度** |
| 対応フォーマット | フィード投稿・リール（ストーリーズは非対応） | 動画 |

※ Instagram公式アプリからなら最大75日先まで予約できるが、Business Suite は29日まで。
　月次サイクルなら Business Suite で足りる。

※ TikTok側の日数・件数上限は情報源によって幅がある（28日/30日など）。
　**最初の月に実機で確認して、この表を実測値に直すこと。**

### ここから導かれる結論

**ボトルネックは TikTok の予約キュー上限（10件程度）。**

週2〜3本なら月8〜12本になるので、月イチでまとめて予約投入しようとすると引っかかる。

→ **予約は2週間ごとに分けて投入する。** 月1回のまとめ投入にしない。

## 月次サイクル

```
月末〜月初
  ├ 前月レポートを提出
  └ 翌月の企画をクライアントに提案・すり合わせ

第1週
  ├ 撮影 または 素材受領
  └ 編集（バッチでまとめて）

第2週
  ├ 完パケ → クライアントへ一括で承認依頼
  ├ 承認 → 前半分を Business Suite / TikTok Studio に予約投入
  └ 投稿開始

第3週
  └ 後半分を予約投入（TikTokのキュー上限を回避）

第4週
  ├ 数字を管理表に記入
  └ レポート作成
```

編集は週1バッチ、投稿は分散。
まとめ編集・分散投稿にしないと、編集の日が来ないまま投稿も止まる。

## 承認フロー

運用代行で事故るパターンは2つしかない。

1. 承認を取らずに出してしまった
2. 承認待ちで投稿が止まった

どちらも承認フローの設計で防げる。

### ルール

**まとめて承認をもらう。** 1本ずつ確認を回さない。
月1回、その月の全本数を一覧で出して、まとめて返事をもらう。
1本ずつ投げると、クライアント側の確認コストが上がり、結果的に返事が遅くなる。

**承認対象は4点セット。**
動画 ／ キャプション ／ ハッシュタグ ／ 投稿予定日 を必ずセットで出す。
動画だけ見せて後からキャプションで揉めるのを防ぐ。

**期限を切る。**
「◯日までに返信がない場合はこの内容で進めます」を運用ルールとして
**事前にクライアントと合意しておく**。合意なしにこれを書くと角が立つので、
契約時か初回打ち合わせで決めておくこと。

**記録を残す。**
メールかチャットのスレッドに残す。口頭承認だけにしない。
管理表の `承認ステータス` と `承認日` を必ず埋める。

### 承認ステータスの値

管理表の `承認ステータス` 列には、次の4つだけを使う。

| 値 | 意味 |
| --- | --- |
| `未提出` | 完パケ前、またはまだクライアントに出していない |
| `承認待ち` | 提出済み、返事待ち |
| `承認済` | OK。予約投入してよい |
| `差戻し` | 修正指示あり。備考欄に内容を書く |

**`承認済` 以外は予約投入しない。** ここだけは例外を作らない。

## コメント・DM対応の線引き

契約時に決めて、書面に残す。曖昧にすると必ず期待値がズレる。

決めること：

- **対応するか、しないか**（契約範囲に含むか）
- 対応する場合、**テンプレの範囲内は自社判断、それ以外はクライアント確認**という線引き
- **ネガティブコメント・クレームは必ずクライアントにエスカレーション。**
  自社判断で返信しない
- **対応時間帯**（平日◯時〜◯時。24時間対応ではないことを明記する）

特に最後が重要。明記していないと「夜中に来たクレームになぜ対応していないのか」になる。

## 月次レポート

**30分で作れる型に固定する。**
作るのに半日かかるレポートは続かない。続かないと契約更新のときに材料がない。

管理表から拾える範囲だけにする。

### 含めるもの

- 投稿本数（Instagram / TikTok それぞれ）
- 合計再生数、フォロワー増減
- **上位3本**と、なぜ効いたかの仮説（1行ずつ）
- **下位3本**と、なぜ効かなかったかの仮説（1行ずつ）
- 翌月の方針（1〜2行）

### 含めないもの

- 細かすぎる指標。読まれないし、質問を呼んで工数が増える
- 「がんばりました」系の記述
- 施策として実行できない考察

### 伸びなかった月の書き方

数字が悪い月ほど、**先にこちらから理由と次の打ち手を出す**。
聞かれてから答えると言い訳に見えるが、先に出すと分析に見える。中身は同じでも印象が違う。

## 立ち上げ時（最初の1ヶ月）にやること

通常サイクルに入る前の、1回だけの作業。

- [ ] Meta：パートナーアクセスの形を確認・必要なら切り替え（`権限とアカウント設計.md`）
- [ ] Meta：こちらが管理者権限を持っていないか確認し、最小権限に落とす
- [ ] TikTok：アカウント開設（メールと2段階認証はクライアント名義で）
- [ ] TikTok：Business Center のパートナー連携を設定
- [ ] TikTok：**BC から実際に何ができるかを実機で確認**し、このドキュメントを更新
- [ ] TikTok：予約投稿の日数・件数上限を実測して上の表を直す
- [ ] 管理表をスプレッドシートにインポートし、クライアントと共有
- [ ] 承認フロー・期限・コメント対応範囲をクライアントと合意し、書面化
- [ ] 解約時の手順を書面化
- [ ] レポート雛形を1本作って、初月から同じ型で出す

## 判断ポイント：ツールを増やすか

Hootsuite / Later / SocialDog のような、IG と TikTok をまとめて管理できる
サードパーティツールもある。

**当面は入れない。** 理由：

- 1クライアント・週2〜3本なら、Business Suite と TikTok Studio の手動運用で足りる
- 純正ツールのほうがプラットフォーム側の仕様変更に強い
- ツール経由の投稿がリーチに影響するかは検証が難しい

**入れるタイミング**：クライアントが3件を超えたとき、または投稿本数が週5本を超えたとき。
そこまでは手動でよい。
